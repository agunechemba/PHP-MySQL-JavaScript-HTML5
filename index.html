Welcome

Hello, Future Web Developer

A complete course in the languages that make the web work.

Although web development has changed over the years, the actual core details of creating a web page have stayed the same. You create a document and put it out on the web for people to view. To do that, you need to learn the special languages that are spoken on the web — not the cryptic shorthand of text messages, but the languages used to create web documents and sites.

This book looks at many aspects of web development: the language used to make web pages, the ways to make those pages look good, the ways to make them accept information from visitors, and the programs that build other pages. It's all broken into manageable pieces so you can consume the information at your own pace.

The book is divided into seven minibooks, each focused on a distinct layer of the web. Book One gets the tools installed — the web server, PHP, and MySQL. Book Two covers HTML and CSS, the two languages of every web page. Book Three covers JavaScript, the language that makes pages come alive. Book Four covers PHP, the language of server-side programming. Book Five covers MySQL, the database that stores your data. Book Six puts all the pieces together into real applications. Book Seven closes with configuration and templating.

The code examples in this book assume you have a computer with a recent version of Windows, Mac OS X, or Linux on it. You don't need to know anything about programming or creating web pages, but you should be comfortable moving around on the computer. Words like files, directories, editor, browser, and installing software should already be familiar.

This is a book meant to be read with your fingers on the keyboard. Type every example. Save it. Reload the browser. Break it. Fix it. Make it your own. The loop — edit, save, reload, repeat — is the whole secret of web development.

Before You Go

  • Seven minibooks cover the technologies of the web, each building on the last.
  • You can read the book in any order, but the early chapters install software later chapters assume.
  • The code examples are meant to be typed, not just read.
  • Every programmer, every day, writes mistakes. That's how we learn.

Book One · Getting Started with PHP & MySQL · Chapter 1

Understanding the Languages of the Web

How the web works, and what each of its languages is for.

The World Wide Web is a large group of computers, known as servers, that exist to provide information when it's requested. The information is requested by software called a web browser. This is the client-server model: the browser is the client, the server provides the information. Web servers and browsers talk to each other using a protocol called HTTP, which is stateless — it doesn't remember what it was doing from one request to the next.

Every website has a unique address called an IP address — four numbers between 0 and 255, separated by dots. Because IP addresses are hard to remember, the Domain Name System (DNS) translates friendly names like www.example.com into the numeric address the computer needs.

Web pages themselves have three primary languages. HTML provides the structure — the headings, paragraphs, images, and links. CSS changes the layout and appearance — fonts, colors, spacing, and positioning. JavaScript provides behaviour — what happens when you click a button or submit a form. On the server side, PHP builds web pages dynamically, often reading data from a MySQL database to decide what to send back.

PHP and MySQL are a popular pair for building dynamic web applications. They're free, web-oriented, easy to use, fast, and well-supported. Apache — the most widely used web server — receives each request and, when the file is PHP, hands it to the PHP processor before sending the result to the browser.

<!doctype html>
<html>
<head>
  <title>My First Page</title>
</head>
<body>
  <h1>Hello, world!</h1>
  <p>This page is written in HTML.</p>
</body>
</html>

You don't need fancy software to build a page. You need a text editor to write the code and a browser to view the result. That loop — edit, save, reload — is the whole secret of web development.

Key Ideas

  • The web runs on the client-server model, connected by HTTP.
  • DNS translates domain names into IP addresses.
  • HTML structures, CSS styles, JavaScript scripts.
  • PHP and MySQL build dynamic pages on the server.
  • Apache is the web server that ties them all together.

Try It Yourself

  1. Type the sample HTML into a new file, save it as index.html, and open it in your browser.
  2. Change the heading to your own name and reload the page.
  3. Add a second paragraph below the first.

Book One · Getting Started with PHP & MySQL · Chapter 2

Installing a Web Server

Apache — the software that sends pages to the world.

Before you can install PHP or MySQL, you need a web server. Apache httpd is the most popular choice: free, open source, cross-platform, and stable. It's available in three versions — 2.0, 2.2, and 2.4 — and all three are still supported. Check for an existing installation by typing http://localhost into your browser. If a page appears, a web server is already running.

If you're using a hosted website or a company server, you don't need to install Apache at all. If you're developing locally, you do. Windows doesn't come with Apache; Linux usually includes it; Macs include it but it may not be started. On any platform, the all-in-one kits — XAMPP, WAMPServer, MAMP — bundle Apache, PHP, and MySQL into one convenient installer.

Once Apache is installed, you control it with the apachectl script on Linux, Unix, and Mac, or through the Start menu on Windows. To start: /usr/local/apache/bin/apachectl start. To stop: apachectl stop. To restart (which you need after editing configuration): apachectl restart. On Windows with a service installation, Apache starts automatically when the computer boots.

Apache reads its configuration from a file called httpd.conf. The two directives you'll most often change: DocumentRoot, which tells Apache where to find web page files, and Listen, which tells it which port to accept connections on (default 80). Remember to restart Apache after any change — the new settings take effect only at the next start.

DocumentRoot "C:/Program Files/Apache Group/Apache/htdocs"
Listen 80

To confirm the installation is working, type httpd -v to see the version and httpd -l to see the modules. If both commands return sensible output, Apache is installed and ready.

Key Ideas

  • Apache httpd is the most popular free web server, in versions 2.0, 2.2, and 2.4.
  • All-in-one kits (XAMPP, WAMPServer, MAMP) bundle Apache, PHP, and MySQL.
  • Control Apache with apachectl on Unix/Mac, or through Windows Services.
  • Configure via httpd.conf — change DocumentRoot and Listen; restart after.

Try It Yourself

  1. Visit http://localhost. Is a page displayed? What does it say?
  2. Find httpd.conf on your system. What is its DocumentRoot value?
  3. Run httpd -v from a command prompt. What version of Apache do you have?

Book One · Getting Started with PHP & MySQL · Chapter 3

Installing PHP

Getting the server-side language ready to run.

PHP may already be installed — some Linux and Mac distributions include it. Windows doesn't come with PHP. To check, search for files named php* on your hard drive. If you find them, the next question is whether PHP is activated and configured. To find out, create a test file with a call to phpinfo() and load it through your web server.

Download PHP from www.php.net. If you're installing for the first time and building your first website, download PHP 5 (or PHP 6, if it's available by the time you read this). PHP 5 and 6 are significantly different from PHP 4; if you're maintaining an existing site, check its version carefully.

On Unix, Linux, and Mac, install PHP as an Apache module — it's faster and more secure than running it as a standalone interpreter. Download the source, unpack the tarball, run ./configure --with-apxs2 (plus any other options you need), then make and make install. The configure step checks that the software PHP needs is present, and tells you if something is missing.

On Windows, extract the Zip file into c:\php — not Program Files, because the space in the path causes problems. Then open php.ini (copy php.ini-dist to php.ini if it doesn't exist) and set your options. You must also configure Apache to recognise PHP files: uncomment the LoadModule php5_module line and add AddType application/x-httpd-php .php in httpd.conf.

Configure PHP through php.ini. Important settings: turn off magic quotes if you're on PHP 5 or earlier, set your local time zone, and on Windows with IIS, turn off cgi.force_redirect. Save the file, then restart Apache so it picks up the new settings.

<!doctype html>
<html>
<head><title>PHP Test</title></head>
<body>
  <p>This is an HTML line</p>
  <?php echo "<p>This is a PHP line</p>"; phpinfo(); ?>
</body>
</html>

Save this as test.php in your Document Root. Then visit http://localhost/test.php through your browser — never by selecting File → Open. If you see two lines of output and a long table of PHP settings, PHP is installed and working. If you see only the HTML, PHP isn't being processed.

Key Ideas

  • PHP is often already installed on Linux and Mac; on Windows you install it yourself.
  • On Unix, install PHP as an Apache module for speed and security.
  • On Windows, install into c:\php and configure httpd.conf.
  • Test with test.php and phpinfo().

Try It Yourself

  1. Create test.php with the sample code and load it through your browser. What do you see?
  2. In the phpinfo() output, find the Configuration File Path. Where does PHP look for php.ini?
  3. Change date.timezone in php.ini, restart Apache, and reload the test page.

Book One · Getting Started with PHP & MySQL · Chapter 4

Setting Up MySQL

The database that stores what your application needs.

MySQL is the database system that will hold your application's data. It may already be installed on Linux and Mac; Windows doesn't include it. To check whether MySQL is running on Windows, look in Services. On Linux, Unix, and Mac, type ps -ax and look for a process called mysqld. If MySQL is installed but not running, start it — with the Services panel on Windows, or service mysqld start on Linux.

Download MySQL from www.mysql.com. Community Server is free and appropriate for websites; Enterprise Server is a paid subscription. On Windows, use the MSI installer and choose Developer Machine when prompted for a configuration type. On Linux, install from RPM files or from your distribution's package manager. On Mac, use the DMG file, or compile from source if you need features the DMG doesn't include.

Configure MySQL through my.ini (Windows) or my.cnf (Unix, Linux, Mac). Three directives you might adjust: the port (3306 by default), basedir (where MySQL is installed), and datadir (where the databases are stored). On Windows, MySQL runs as a service and starts automatically when the computer boots. On Linux and Mac, a script called mysql.server starts and stops it.

Activate MySQL support in PHP. On Windows, uncomment extension=php_mysql.dll (or php_mysqli.dll) in php.ini, and make sure the DLLs are on the system path. On Linux and Mac, MySQL support must be compiled in at install time with --with-mysql or --with-mysqli.

[mysqld]
port = 3306
basedir = C:/Program Files/MySQL/MySQL Server 5.0/
datadir = C:/Program Files/MySQL/MySQL Server 5.0/Data/

Test MySQL by connecting with the mysql client: type mysql -u root -p, enter your password, and you'll see the MySQL monitor prompt. Type quit to exit. If you see the welcome message, MySQL is installed and working.

Key Ideas

  • MySQL is a free, open-source RDBMS — Community Server is the version for websites.
  • Configure via my.ini or my.cnf.
  • On Windows, MySQL runs as a service; on Linux/Mac, use mysql.server.
  • Activate MySQL support in PHP with extension=php_mysql.dll on Windows, or --with-mysql at compile time on Unix.

Try It Yourself

  1. Find the MySQL configuration file on your system. What is its port setting?
  2. Connect to MySQL with the mysql client. What version does the welcome message report?
  3. Run phpinfo() and look for a MySQL section. Is MySQL support activated?

Book One · Getting Started with PHP & MySQL · Chapter 5

Setting Up Your Web Development Environment with XAMPP

Apache, PHP, and MySQL in one installer — the fastest path to a working environment.

XAMPP is a popular all-in-one kit that installs Apache, MySQL, and PHP in one procedure. It also installs phpMyAdmin, a browser-based tool for managing MySQL databases. It's available for Windows, Mac, and several Linux distributions, and is intended as a development environment — it is configured to be as open as possible, and is not secure for production use without tightening.

Download XAMPP for Windows from www.apachefriends.org. On Windows Vista, 7, or 8, don't install into Program Files — Windows protects that folder, and PHP has trouble with the space in the path. Accept the default c:\xampp. During installation, select Install Apache as Service and Install MySQL as Service, so both start automatically when the computer boots.

The XAMPP Control Panel shows the status of Apache, MySQL, and other components. You can use it to start and stop each one individually, which is handy when you need to restart after a configuration change. The panel lives in the system tray while it's running. The green "Running" indicator next to Apache and MySQL is the sign that your environment is ready.

Test the installation by visiting http://localhost — you should see the XAMPP welcome page. Click Status to see which components are activated. To test PHP, create test.php in c:\xampp\htdocs containing a call to phpinfo() and visit http://localhost/test.php. Scroll down to confirm a MySQL section is present — that means the connection between PHP and MySQL is working.

date.timezone = America/Los_Angeles
upload_max_filesize = 100M
memory_limit = 256M

The XAMPP configuration files live in the XAMPP directory, not in the system directories the individual software's documentation mentions. PHP's is c:\xampp\php\php.ini; Apache's is c:\xampp\apache\conf\httpd.conf; MySQL's is c:\xampp\mysql\bin\my.cnf. Restart Apache from the Control Panel after editing php.ini. If something goes wrong, the standard fix is to uninstall XAMPP (after stopping the services) and reinstall.

Key Ideas

  • XAMPP bundles Apache, MySQL, PHP, and phpMyAdmin in one installer.
  • It's a development environment, not a production one — tighten security before going live.
  • Install into c:\xampp; install services so they start automatically.
  • Edit configuration files in the XAMPP directory, then restart Apache.

Try It Yourself

  1. Visit http://localhost. What XAMPP page appears? Click the Status link and check which components are activated.
  2. Create c:\xampp\htdocs\test.php with a phpinfo() call and load it in your browser.
  3. Change a setting in c:\xampp\php\php.ini, save, and restart Apache from the Control Panel.

Book Two · HTML and CSS · Chapter 6

Creating a Basic Page with HTML

Structure, semantics, and the first page you'll actually build.

At its heart, HTML is just a document — much like a document you'd create in a word processor. But where a word processor uses its own proprietary format, HTML uses a plain text format that every web browser can read. You create HTML with a text editor; you view the result in a browser. Both are just programs.

An HTML document has three parts. The root element (<html>) wraps the whole thing. The head section contains information about the page — the title, the character set, links to stylesheets and scripts. The body section contains the visible content — headings, paragraphs, images, links.

HTML5 uses a very simple doctype: <!doctype html>. This tells the browser to follow the HTML5 rules. Older doctypes were long and complicated; HTML5's is refreshingly short.

Inside the body, use the right element for the job. <p> for paragraphs. <h1> through <h6> for headings, in descending order of importance. <div> for a generic block container. <span> for a generic inline container. <br> for a line break. <hr> for a thematic break. <a href="..."> for a link. <img src="..." alt="..."> for an image. This is semantic markup — using the right element for the right job, which helps search engines and assistive technology understand your page.

<!doctype html>
<html>
<head>
  <title>My First Document</title>
</head>
<body>
  <h1>My Web Page</h1>
  <p>Welcome to my web page.</p>
  <h2>My Books</h2>
  <p>You can find information about my books here.</p>
</body>
</html>

Lists come in two flavours: <ul> for bulleted (unordered) lists, and <ol> for numbered (ordered) lists. Inside, each item is wrapped in <li>. Tables use <table> with rows (<tr>), header cells (<th>), and data cells (<td>). When you're done, validate the page with the W3C Markup Validation Service at validator.w3.org — valid HTML doesn't guarantee a beautiful page, but it guarantees the browser can parse your page correctly.

Key Ideas

  • An HTML document has a root, a head, and a body.
  • HTML5 uses the simple <!doctype html> doctype.
  • Use the right semantic element for each piece of content.
  • Lists (ul, ol, li) and tables (table, tr, th, td) structure tabular and enumerated data.

Try It Yourself

  1. Build the sample page in your editor and open it in your browser.
  2. Add an unordered list of three favourite things below the second paragraph.
  3. Validate your page at validator.w3.org. Did it pass?

Book Two · HTML and CSS · Chapter 7

Adding Style with CSS

Selectors, fonts, colors, and the layouts that make a page look like a page.

CSS complements HTML by providing a look and feel to web pages. HTML gives you a structure; CSS decides what that structure looks like. It can change colors, fonts, spacing, borders, backgrounds — even the layout of the whole page. It's the difference between a document and a design.

You connect CSS to a page in three ways. Inline styles go directly on an element via the style attribute. Internal style sheets live in a <style> element in the head. External style sheets live in a separate .css file, linked with a <link> element. External is the most reusable — one file, many pages, one edit to change them all.

Selectors target elements. Use the element name (div) to select every element of that kind, a class (.boldText) to select every element with that class attribute, an id (#myName) to select the one element with that id, or a combination (div span) to target elements based on their position in the page's hierarchy.

Then the visual properties. font-family sets the typeface, with a list of fallbacks. font-size sets the size, using percentages or ems so users can scale. color sets text color, using a name or hex code. border draws a border — thickness, style, color in one rule. list-style-type changes bullets or removes them. background-color and background-image set what's behind the content. width, margin, padding, and float control the layout.

body {
  font-family: arial, helvetica, sans-serif;
  font-size: 90%;
}
.boldText {
  font-weight: bold;
}
span {
  font-style: italic;
  color: #0000FF;
}
.addBorder {
  border: 3px double black;
  padding: 5px;
}

With those rules, you can build a single-column layout (a container centred with margin: 0 auto), a two-column layout (a content column floated left, a sidebar floated right), and full pages with headers, menus, footers, and content. Once you've set up your CSS, changing the look of every page on the site takes one edit.

Key Ideas

  • CSS can be inline, internal, or external — external is most reusable.
  • Selectors: element, class (.), id (#), hierarchy (space).
  • Fonts, colors, borders, lists, and backgrounds are all CSS properties.
  • Layouts are built from width, margin, padding, and float.

Try It Yourself

  1. Create a style.css file and link it from your page. Add a body rule with a font-family.
  2. Add a .boldText class and apply it to a paragraph.
  3. Set a container div to width: 600px; margin: 0 auto; and see it centre.

Book Two · HTML and CSS · Chapter 8

Creating and Styling Web Forms

Gathering information from users — and making the form usable.

Web forms are how a page gathers information. A <form> element wraps a set of fields. Its action attribute says where the data goes; its method attribute (GET or POST) says how it gets there. GET puts the data in the URL — fine for small forms, and easier to bookmark. POST sends the data invisibly, with no length limit — fine for larger forms and for anything sensitive.

The <input> element covers most of the ground, with its type attribute choosing the field. type="text" gives a single-line text box; size and maxsize control its dimensions. type="password" masks the input. type="checkbox" creates a checkbox; type="radio" creates a radio button. A group of radio buttons with the same name allows only one selection. type="submit" creates the button that sends the form; type="reset" clears it.

For longer text, use <textarea>. For dropdowns, use <select> with <option> children — add selected="selected" on one option to choose the default. For grouping, use <fieldset> with a <legend> caption. For each field, use a <label> — either wrapping the field or connected via for and id — so users can click the label to focus the field, and assistive technology knows what the field is for.

<form action="#">
  <fieldset>
    <legend>Form Information</legend>
    <div>
      <label for="username">Name:</label>
      <input id="username" type="text" name="username">
    </div>
    <div>
      <label for="email">E-mail Address:</label>
      <input id="email" type="text" name="email">
    </div>
    <div>
      <input type="submit" name="submit" value="Send Form">
    </div>
  </fieldset>
</form>

Once the form exists, style it with CSS. A common pattern: each field row is a .form-field div; inside, the label is floated left with a fixed width, the input is floated right with a fixed width. That aligns labels and fields into neat columns. Add a class to the submit button to control its own styling.

Key Ideas

  • Form: <form> with action and method (GET or POST).
  • Input types: text, password, checkbox, radio, submit, reset.
  • Use select for dropdowns, textarea for long text, fieldset/legend for groups.
  • Always use <label> — for accessibility and usability.

Try It Yourself

  1. Build the sample form and load it in your browser.
  2. Add a checkbox, a group of radio buttons, and a textarea.
  3. Style the fields with a .form-field class, floats, and fixed widths.

Book Three · JavaScript · Chapter 9

Understanding JavaScript Basics

What it is, what it isn't, and how to add it to a page.

JavaScript is a very powerful language that runs inside the web browser. HTML gives a page structure; CSS gives it appearance; JavaScript gives it behaviour. With JavaScript you can make pages come alive — auto-populating form fields, responding to clicks and keypresses, moving things around on the page, communicating with the server behind the scenes.

One thing to get straight immediately: JavaScript is not Java. The two languages are completely unrelated. Java is a heavy language that requires an extra install to run; JavaScript is built into every web browser and requires nothing. The name was a marketing decision made when Java was shiny and new.

You add JavaScript to a page with the <script> tag. Inside the tag, put your code. The tag can go in the head or in the body — both work. You can also use an external file with the src attribute, which is cleaner for anything longer than a few lines.

<script type="text/javascript">
  alert("hello");
</script>

<script type="text/javascript" src="externalfile.js"></script>

JavaScript has its own syntax. Comments start with // or sit between /* */. Statements end with semicolons. Variables are declared with var. Functions are blocks of reusable code. The browser's developer console — usually opened with F12 — shows error messages and lets you run snippets live.

One limitation to know up front: JavaScript runs in the user's browser, so it can be turned off entirely. Anything that's truly essential — like validation that absolutely must happen — has to be done on the server side, in PHP. This is a theme that will come up again in Book Six, when we validate forms for real.

Key Ideas

  • JavaScript provides behaviour; it runs in the browser.
  • It has nothing to do with Java.
  • Add it with a <script> tag or an external file.
  • It can be turned off in the browser — so critical logic must live on the server too.

Try It Yourself

  1. Add a <script> tag to your page with alert("hello"); in it. Reload — did the alert appear?
  2. Move the script to an external file and reference it with src.
  3. Open the console (F12). What does console.log("Test!") do?

Book Three · JavaScript · Chapter 10

Building a JavaScript Program

Variables, conditionals, loops, functions, objects, and the DOM.

Programming starts with the basics. Variables hold data: var myVariable = 4; creates a variable and sets it to 4. Arrays hold multiple values: var myArray = ["Steve","Jakob","Rebecca","Owen"];. Strings hold text — anything in quotes. Numbers support arithmetic: +, -, *, /. The + sign also concatenates strings.

Conditionals make decisions. The form is if (condition) { ... } else if (condition) { ... } else { ... }. JavaScript has two equality operators: == compares value (with type coercion) and === compares value and type. For example, "5" == 5 is true, but "5" === 5 is false. Prefer === to avoid surprises.

Loops repeat. A for loop is the workhorse: for (var i = 0; i < 10; i++) { ... }. Inside, you can use i to count. A while loop repeats as long as a condition is true. Both can go wrong — an infinite loop will freeze the tab — so always make sure something inside the loop changes the value the condition checks.

Functions bundle reusable code. Declare one with function addNumbers(num1, num2) { return num1 + num2; } and call it with addNumbers(49, 2). The return statement sends a value back to the caller; without it, the function returns undefined.

var myVariable = 4;
alert(myVariable);

for (var i = 0; i < 10; i++) {
  alert("The variable i is currently set to " + i);
}

function addNumbers(num1, num2) {
  return num1 + num2;
}
var result = addNumbers(49, 2);

Objects hold multiple named values: var ball = { "color": "white", "type": "baseball" };. Access a property with dot notation: ball.color. Add a property with ball.weight = 15;. Loop through an object's properties with for (var prop in ball) { alert(ball[prop]); }.

Finally, JavaScript can interact with the HTML page through the DOM. The key function is document.getElementById("myDiv"), which returns a reference to the element with that id. From there you can read or change its content — theDiv.innerHTML — or its style — theDiv.style.border = "3px solid black". Other browser objects — navigator, location — give you information about the browser and the current page, and let you redirect to another URL.

Key Ideas

  • Variables, arrays, strings, numbers — the data building blocks.
  • if / else if / else makes decisions; prefer === to ==.
  • for and while repeat; watch out for infinite loops.
  • Functions accept parameters and return values.
  • Objects hold named properties; the DOM exposes the page as objects.

Try It Yourself

  1. Declare a variable, an array, and an object. Log each to the console.
  2. Write a for loop that logs only the even numbers from 1 to 20.
  3. Write a function that returns the larger of two numbers, and call it with several pairs.

Book Three · JavaScript · Chapter 11

Adding jQuery

The library that makes JavaScript's DOM work feel like CSS.

jQuery is a JavaScript library — a collection of code you add to your page to make writing JavaScript easier. You still use JavaScript with jQuery; you just use less of it, and the code you write looks a lot like CSS selectors. Its big advantage is that it smooths over the browser differences that otherwise make front-end work so tedious.

You install jQuery by downloading it from jquery.com (save the file into your Document Root), or by pointing at a CDN-hosted copy from Google or Microsoft. The CDN approach is convenient for development; a local copy is more reliable for production. Either way, you add it to the page with a <script> tag, usually in the head.

<script type="text/javascript"

$(document).ready(function() {

Reacting to Events with JavaScript and jQuery

When the user does something, your code responds.

Events are things that happen. Form events include selecting a checkbox or submitting a form. Mouse events include clicks and movement. Keyboard events include key presses. Reacting to form submission is one of the most common things JavaScript does. Attach a submit() handler to the form, and you can inspect its values before it goes to the server. $(document).ready(function() {

      alert("Name can't be blank");
      event.preventDefault();
      return false;
    }

Understanding PHP Basics

Tags, variables, types, arrays, dates, and errors.

PHP is an embedded scripting language. Its code lives inside HTML files, between <?php and ?> tags. When the web server gets a request for a .php file, it scans for PHP sections, hands those to the PHP processor, and replaces each one with its output before sending the result to the browser. The browser never sees the PHP code — only what the PHP code produces.

PHP syntax is straightforward. Simple statements end with semicolons. Multiple statements can go on one line, or span many. Complex statements — if statements, loops, functions — use curly braces to group statements into blocks. Whitespace doesn't matter to PHP; use it freely to make the code readable.

Variables start with a dollar sign: $age = 12; creates a variable named $age and sets it to 12. Names must start with a letter or underscore, can contain letters, numbers, and underscores, and are case-sensitive. Use descriptive names. You can assign strings (quoted), numbers (unquoted), arrays, and more. Constants are like variables but can't change after being defined: define("COMPANY", "My Fine Company");.

<?php
$age = 12;
$name = "Little Bo Peep";
echo $age;
echo $name;

$weekday = "Monday";
var_dump($weekday);  // string(6) "Monday"
?>

PHP has eight data types: integer, float, string, boolean, NULL, array, object, resource. PHP determines the type automatically based on what you assign. It also converts types automatically when needed — adding an integer to a float produces a float, for example. You can force a type with a cast: (int) $var.

Arrays hold multiple values under one name. Create one with $cities[] = "Phoenix"; or $cities = array("Phoenix", "Tucson", "Flagstaff");. Access elements with square brackets. Use sort(), asort(), ksort(), and friends to order them. Use foreach to walk through every element in turn. Multidimensional arrays are arrays of arrays.

Dates and times come from the date() function, which formats a Unix timestamp (seconds since January 1, 1970) into a readable string. The time() function returns the current timestamp. strtotime() parses a human-readable date string. PHP displays five types of error messages: parse errors (the script won't run), fatal errors (the script stops), warnings (the script continues, but something is wrong), notices (the script continues, but something is unusual), and strict (coding standards). When something goes wrong, the message names the file and line.

Key Ideas

  • PHP code lives between <?php and ?> tags, embedded in HTML.
  • Variables start with $, are case-sensitive, and should be descriptively named.
  • PHP has eight types; it converts between them automatically as needed.
  • Arrays hold multiple values; foreach walks through them.
  • Error messages name the file and line where the problem occurred.

Book Four · PHP · Chapter 15

Building PHP Scripts

Conditions, loops, functions, and the organization that keeps them clean.

PHP scripts are more than one statement after another. They branch, repeat, and reuse code. The building blocks for all of that are conditions, loops, and functions.

Conditions test values. PHP's comparison operators are == (equal in value), === (equal in value and type), != and <> (not equal), >, <, >=, <=. Compare strings, numbers, or variables. Join comparisons with and, or, or xor — and remember that and binds tighter than or. Use parentheses to be explicit.

For pattern matching, use preg_match(). A regular expression like /^[A-Za-z].*$/ matches any string that begins with a letter. /^[0-9]{5}$/ matches exactly five digits. /^.+@.+\.com$/ matches a common email format. Regex is how you validate things the browser can't be trusted to check.

Conditional statements decide what to do. if runs a block when a condition is true; elseif tests additional conditions; else catches everything else. switch handles many discrete cases more cleanly than a long chain of if/elseif — each case ends with break to stop fall-through.

Loops repeat. for bundles a counter, a condition, and an increment. while loops as long as a condition is true. do..while runs at least once and then checks. Watch out for infinite loops — a loop whose condition never becomes false. break exits a loop early; continue skips the rest of the current iteration.

<?php
if ($score > 92) {
  $grade = "A";
} elseif ($score > 83) {
  $grade = "B";
} else {
  $grade = "C";
}

for ($i = 1; $i <= 3; $i++) {
  echo "$i. Hello World!<br />";
}

function compute_salestax($amount, $custState) {
  switch ($custState) {
    case "OR": $rate = 0; break;
    case "CA": $rate = 1.0; break;
    default:   $rate = 0.5; break;
  }
  return $amount * $rate;
}
echo compute_salestax(2000.00, "CA");
?>

Functions bundle reusable code. Declare with function name($param1, $param2) { ... }, call with name($arg1, $arg2). Use return to send a value back. Pass by value by default; add & before a parameter name to pass by reference. Default values let you call with fewer arguments: function add_2_numbers($a = 1, $b = 1).

Organize scripts by separating logic from display. Put reusable functions in include files (include("functions.inc");, require("functions.inc");, include_once, require_once). Store the include files outside the Document Root, or give them a .php extension, to keep them from being visible to the world.

Key Ideas

  • Comparison operators: ==, ===, !=, >, <, >=, <=.
  • Regular expressions (preg_match) validate input by pattern.
  • if/elseif/else and switch branch; for, while, do..while loop.
  • Functions accept parameters, return values, and can have defaults.
  • Include files separate display from logic and keep code reusable.

PHP and Your Operating System

Files, commands, FTP, and the flat files that hold data outside MySQL.

PHP can interact with the operating system — reading and writing files, running system commands, transferring files over FTP, exchanging data with other programs. Most applications need only MySQL, but some need the extra reach.

For files, use file_exists(), is_file(), is_dir(), filesize(), filemtime() and the other file information functions. Copy with copy(), rename with rename(), delete with unlink(). Create directories with mkdir(); list their contents with opendir() and readdir() in a while loop.

For system commands, PHP offers four approaches. Backticks ($output = `dir c:\php`;) execute and return output. system() displays output and returns the last line. exec() does not display output; it stores it in an array and returns the last line. passthru() displays raw output without returning it. Use any of these only when the PHP function you need doesn't exist — and never with unvalidated user input, because that's how command injection happens.

<?php
$result = file_exists("stuff.txt");
copy("fileold.txt", "filenew.txt");
rename("oldname.txt", "newname.txt");
unlink("badfile.txt");

if (!is_dir("mynewdir")) {
  mkdir("mynewdir");
}

$dh = opendir("/topdir/testdir");
while ($filename = readdir($dh)) {
  echo "$filename\n";
}
?>

For FTP, use ftp_connect(), ftp_login(), ftp_nlist(), ftp_get() (download), ftp_put() (upload), and ftp_close(). FTP support must be enabled at install time on Unix/Linux/Mac (--enable-ftp); on Windows it's on by default. FTP is inherently insecure — the password travels in plain text — so for anything sensitive, prefer SCP or SFTP.

For reading and writing files, the pattern is: open with fopen() (mode r to read, w to write, a to append), write with fwrite(), read with fgets() in a loop until feof(), close with fclose(). For whole-file reads, file() gives you an array of lines, file_get_contents() gives you a single string.

For exchanging data, use comma-delimited files (CSV) with fgetcsv() to read and a loop to write, or use sqlite_open() and sqlite_query() to store structured data in a flat file without a full database server.

Key Ideas

  • File functions: file_exists, is_file, copy, rename, unlink, mkdir, opendir/readdir.
  • System commands: backticks, system(), exec(), passthru() — never with user input.
  • FTP: ftp_connect, ftp_login, ftp_nlist, ftp_get, ftp_put.
  • Read/write files with fopen, fwrite, fgets, fclose.

Object-Oriented Programming

Classes, objects, inheritance, interfaces, and the philosophy of modelling a problem.

Object-oriented programming isn't just different syntax — it's a different way of analyzing a problem. The application is designed by modelling the programming problem: you identify the objects that make up the problem, then write classes that define what those objects can do.

An object is an instance of a class. The class is the template; the object is the thing made from the template. A class has properties (variables that hold data) and methods (functions that do things). Properties have access modifiers: public (accessible from anywhere), private (accessible only inside the class), protected (accessible inside the class and its children). Good practice is to keep properties private and provide public methods to access them.

Inside the class, the special variable $this refers to the current object. Use it to access properties and call methods: $this->gas, $this->addGas(5). Use __construct() to run code when the object is created. Use __clone() when an object is cloned. Use __destruct() when the object is destroyed.

<?php
class Car {
  private $gas = 0;
  private $color = "red";

  function __construct($amt) {
    $this->gas = $amt;
    echo "Car created with {$this->gas} gallons\n";
  }

  public function addGas($amount) {
    $this->gas = $this->gas + $amount;
    echo "{$amount} gallons added\n";
  }

  public function buyGas($amount) {
    $this->addGas($amount);
  }
}

$my_car = new Car(5);
$my_car->buyGas(10);
?>

Inheritance lets a class extend another. The parent class defines common properties and methods; the child class gets them all and can add or override. A child class's methods can call the parent's methods with parent::. An abstract class can't be instantiated directly — it exists to be a parent, and any child must implement its abstract methods. An interface is like a pure abstract class — a contract that any implementing class must fulfil.

The final keyword prevents a class from being extended or a method from being overridden. Exceptions handle errors: throw one with throw new Exception("message"); and catch it with try { ... } catch (Exception $e) { ... }. Copy an object with clone. Compare objects with == (equal if same class and properties) or === (identical if they refer to the same instance).

Key Ideas

  • Objects are instances of classes; classes define properties and methods.
  • Access modifiers: public, private, protected.
  • $this refers to the current object inside a method.
  • Inheritance (extends) shares code; abstract classes can't be instantiated; interfaces define contracts.
  • try/catch handles exceptions.

  2. Create two instances and call greet() on each.

Considering PHP Security

Keeping attackers out — and keeping your users' data safe.

Security isn't a feature you add at the end; it's a mindset you adopt from the start. The two layers are server security and application security. Server security means keeping the operating system and web server patched and minimally exposed. Application security means validating every input and escaping every output.

On the server side, harden the operating system by removing unnecessary services and enabling a firewall. Run SuExec so PHP scripts execute under their owners' user IDs rather than the web server's, limiting the damage a vulnerable script can do. Install mod_security, an Apache module that filters incoming requests against a rule set designed to block common attacks.

In php.ini, set the security options: safe_mode = on, open_basedir = directory, expose_php = off, register_globals = off, display_errors = off, log_errors = on, and error_log = filename. Together, these hide PHP's presence, prevent attackers from injecting global variables, and keep errors out of the user's browser while sending them to a log file you can review.

<?php
$inputString = "<b>Hello World</b>";
$safe_string = htmlentities($inputString);
// $safe_string now contains:
// &lt;b&gt;Hello World&lt;/b&gt;

if (!preg_match('/^[A-Za-z\' -]+$/', $name)) {
  echo "Please enter a valid name.";
  exit();
}
?>

On the application side, always assume bad data. The user might type letters where you expect numbers, leave required fields blank, or paste an entire script tag into a comment box. The technique is to validate against what you expect — using regular expressions, string length checks, and type checks — and reject anything that doesn't match.

When you must accept input that you can't fully validate, sanitize it. htmlentities() converts <, >, &, and quotes into HTML entities, preventing cross-site scripting. For database queries, use mysqli_real_escape_string() (or prepared statements) to prevent SQL injection.

For file uploads, disable them entirely if you don't need them (file_uploads = Off in php.ini). If you do need them, set limits on file size and file type, store them outside the web root, and validate the uploaded file's content before trusting it. Consider using PHP's FTP functions — they're safer than the fopen()-based approach for accepting user-uploaded files.

Key Ideas

  • Harden the server: remove unnecessary services, run a firewall, enable SuExec and mod_security.
  • Set the important php.ini security options: display_errors off, register_globals off, log_errors on.
  • Always assume bad data. Validate against expected patterns.
  • Sanitize: htmlentities() for HTML, mysqli_real_escape_string() for SQL.

Tracking Visitors with Sessions

Remembering who a visitor is from one page to the next.

HTTP is stateless. Every request is independent. That's fine for static pages, but it's a problem for anything that needs to remember a user across multiple pages — like a login system. Sessions solve this by giving each visitor a unique identifier and storing their data on the server.

Behind the scenes, sessions use cookies. When the session starts, PHP sends a cookie containing a hash value. The browser sends that cookie back with each subsequent request. PHP looks up the hash, finds the corresponding session data on the server, and makes it available in the $_SESSION array. The user never sees the data — only the hash.

To use sessions, call session_start() at the top of every page that needs them. It either starts a new session (if none exists) or continues an existing one. Then read and write values through $_SESSION:

<?php
session_start();
$_SESSION['accessTime'] = date("M/d/Y g:i:sa");
print "This is page 1<br />";
print "You accessed the application at: " . $_SESSION['accessTime'];
?>

<?php
session_start();
if (!isset($_SESSION['accessTime'])) {
  die(header("Location: page1.php"));
}
print "This is page 2<br />";
print "You accessed the application at: " . $_SESSION['accessTime'];
?>

The example also shows an important habit: check whether a session variable exists before using it. Sessions can time out, and a user might clear their cookies mid-session, in which case the session ID is lost and a new session starts with no data. A common pattern is to set one "app started" flag and check that on every protected page, redirecting to a landing page if it's missing.

To close a session explicitly, call session_write_close(). This is rarely necessary — sessions close automatically when the script ends — but it can be useful if two scripts need to write to the same session at the same time, or if you're about to perform a redirect that might outrun the automatic close. Other useful functions: session_id() gets or sets the current ID, session_name() gets or sets the name, session_destroy() removes all session data.

Key Ideas

  • Sessions remember data about a visitor across multiple pages.
  • Session data is stored server-side and identified by a cookie containing a hash.
  • Call session_start() on every page that uses the session.
  • Check whether session variables exist before using them — sessions can disappear.

  2. Create page2.php that reads the session variable and displays it.

Book Five · MySQL · Chapter 20

Introducing MySQL

How the database works, and how to talk to it.

MySQL is a Relational Database Management System (RDBMS). It manages databases that contain tables, which contain rows and columns, which contain data. A database can exist without data — just a structure, waiting. You create the database, then the tables, then you add data.

The heart of MySQL is the server — the software that handles all your database instructions. To create a new database, you send a message to the server saying "create a new database and call it newdata." The server creates the subdirectory and the necessary files. To add data, you send a message saying what data and where. The server does the rest.

You communicate with MySQL using SQL — Structured Query Language. SQL is almost English: statements start with a verb (CREATE, INSERT, SELECT, UPDATE, DELETE, DROP, ALTER), followed by words and phrases that tell MySQL what to act on. A query like SELECT lastName FROM Member retrieves all last names from the Member table. A more specific query adds a WHERE clause and an ORDER BY.

SELECT lastName FROM Member

SELECT lastName, firstName FROM Member
WHERE state = 'CA' AND city = 'Fresno'
ORDER BY lastName

You can send SQL queries in two ways: through the mysql client (a text-based program installed with MySQL), or through PHP's built-in functions. The client is good for quick tests and administration; PHP is how your application talks to the database at runtime.

MySQL protects your data with accounts. Each account has a name, a hostname (the computer it can connect from), a password, and a set of privileges. No one can access your data without an account. Privileges specify what each account can do — select, insert, update, delete, create, drop. The account and its privileges are checked at connection time and again at every statement.

Key Ideas

  • MySQL is an RDBMS; data lives in tables with rows and columns.
  • SQL is the language: statements start with a verb, followed by specifics.
  • Send queries through the mysql client or through PHP functions.
  • Accounts and privileges protect data.

Administering MySQL

Accounts, backups, restores, and the upgrade path.

As MySQL administrator, you're responsible for keeping the database running, secure, and backed up. When MySQL is first installed, it creates a default account called root with all privileges. If it was installed without a password, the first thing you should do is set one. Root is not the account your PHP scripts should use — create a separate account with just the privileges your application needs.

Control access with accounts. Each account is identified by its name and hostname together: phpuser@localhost. The hostname can be a domain name, an IP address, or a wildcard (% matches any host). Passwords are encrypted before being stored. Privileges are granted on specific databases, tables, or columns — you can give an account SELECT on everything but INSERT on nothing.

CREATE USER phpuser@localhost IDENTIFIED BY 'A41!14a!';

GRANT SELECT ON ProductCatalog.* TO phpuser@localhost;

SET PASSWORD FOR phpuser@localhost = PASSWORD('newpassword');

SHOW GRANTS FOR phpuser@localhost;

REVOKE ALL ON *.* FROM phpuser@localhost;

DROP USER phpuser@localhost;

Back up your database with mysqldump. It produces a text file containing all the SQL statements needed to recreate the database — the CREATE statements for each table and the INSERT statements for each row. Store multiple copies: one local for quick restore, one on another computer, one offsite. Restore by running the backup file through the mysql client after adding a CREATE DATABASE statement to the top.

Upgrading MySQL requires care. Back up first. Read the upgrade notes for your version. MySQL recommends not skipping versions — upgrade to each intermediate release in turn. After upgrading, run mysql_upgrade to repair files and upgrade system tables.

Key Ideas

  • Don't use the root account for application access — create a limited account.
  • Accounts are identified by name and hostname; privileges control what they can do.
  • Back up with mysqldump, store copies in multiple locations.
  • Upgrade carefully, back up before, run mysql_upgrade after.

Designing and Building a Database

Choosing data, organizing tables, and creating the structure that holds it all.

Designing a database is the most important step. Get it wrong, and you'll be reworking it later. The process: choose the data, identify the objects (each object becomes a table), identify the attributes (each attribute becomes a column), choose a primary key, define defaults, and identify which columns require data.

Store each piece of information in one place. If you find yourself entering the same data in multiple rows — like a publisher's address repeated for every book — split it into a separate table and reference it by ID. That's the whole point of a relational database: tables relate to each other through shared columns. A customer order table holds a customerID column that matches the customerID in the customer table. One customer, many orders, all linked by the same ID.

MySQL data types: CHAR(length) for fixed-length strings, VARCHAR(length) for variable-length strings, TEXT for long text, INT(length) for integers, DECIMAL(length,dec) for exact decimals, DATE, TIME, DATETIME for dates and times, ENUM("val1","val2",...) for a fixed set of allowed values, and SERIAL as a shortcut for BIGINT UNSIGNED NOT NULL AUTO_INCREMENT.

CREATE DATABASE CustomerOrderInformation;

CREATE TABLE Customer (
  customerID SERIAL,
  lastName VARCHAR(50),
  firstName VARCHAR(40),
  street VARCHAR(50),
  city VARCHAR(50),
  state CHAR(2),
  zip CHAR(10),
  email VARCHAR(50),
  phone CHAR(15),
  fax CHAR(15),
  PRIMARY KEY(customerID)
);

Once the tables are built, change their structure with ALTER TABLE. Add a column with ALTER TABLE ... ADD column definition. Change a column's type with MODIFY. Rename a column with CHANGE. Drop a column with DROP. Rename a table with RENAME. Every change is a chance to make the database better fit the application.

Key Ideas

  • Design first: choose data, define tables, columns, and primary keys.
  • Store each piece of information once; relate tables by shared columns.
  • Choose the right data type: VARCHAR, INT, DECIMAL, DATE, ENUM.
  • Build with CREATE DATABASE and CREATE TABLE; change with ALTER TABLE.

Book Five · MySQL · Chapter 23

Using the Database

Adding, retrieving, updating, and removing data.

An empty database is like an empty cookie jar — nothing comes out. A useful database stores data in, and delivers data on request. The four operations are add, retrieve, update, and remove — often called CRUD (Create, Read, Update, Delete).

Add data with INSERT: list the columns and then the values. If you're inserting into every column, you can omit the column list — MySQL assumes values are in table order. For bulk data, use LOAD DATA INFILE to read from a delimited text file — commas or tabs separate fields; newlines separate rows.

Retrieve data with SELECT. SELECT * gets every column. Name specific columns to narrow the output. Add ORDER BY to sort (add DESC to reverse). Add WHERE to filter rows: comparison operators (=, >, <, BETWEEN, IN, LIKE), combined with AND and OR. Add LIMIT to restrict how many rows come back. Add DISTINCT to eliminate duplicates.

INSERT INTO Customer (lastName, street, city, state, zip, email, phone, fax)
VALUES ('Contrary', '1234 Garden St', 'Garden', 'NV', '88888',
        'maryc@hergarden.com', '(555) 555-5555', '');

SELECT lastName, firstName FROM Customer
WHERE state = 'CA' AND city = 'Fresno'
ORDER BY lastName;

UPDATE Customer
SET street = '3423 RoseLawn', phone = '555-555-5555'
WHERE lastName = 'Contrary';

DELETE FROM Customer WHERE lastName = 'Contrary';

Combine data from multiple tables with UNION (stack result sets one after another) or JOIN (put tables side by side, matching rows by a shared column). An inner join returns only rows that match in both tables. A left join returns all rows from the left table, filling in NULLs where the right has no match. A right join does the same from the right table's perspective.

Update data with UPDATE ... SET column = value WHERE condition. The WHERE clause is essential; without it, every row is updated. Remove data with DELETE FROM ... WHERE condition; again, the WHERE clause is essential. To drop a column, use ALTER TABLE ... DROP column. To drop a whole table, DROP TABLE tablename. To drop a whole database, DROP DATABASE databasename. All three are irreversible — back up before you use them.

Key Ideas

  • Add data with INSERT or LOAD DATA INFILE.
  • Retrieve with SELECT, narrowing via WHERE, ORDER BY, LIMIT, DISTINCT.
  • Combine tables with UNION or JOIN (inner, left, right).
  • Update with UPDATE, remove with DELETE — always with a WHERE clause.

  3. Use UPDATE to change one column of one row, then verify with a SELECT.

Book Five · MySQL · Chapter 24

Communicating with the Database from PHP Scripts

Wiring PHP to MySQL — connecting, querying, and handling errors.

PHP doesn't understand SQL, but it can send it. The pattern is: establish a connection, send the query, handle the result, close the connection. PHP's MySQL functions handle all the networking details.

PHP has two sets of functions for MySQL: the older mysql functions and the newer mysqli (MySQL Improved) functions. This book assumes mysqli — it's required for MySQL 4.1 and later, and it's what modern hosts provide. If your host only offers mysql, the syntax is mostly the same but function names lose the i and the connection parameters differ slightly.

Connect with mysqli_connect(), passing the host, the account name, the password, and the database name. Then send queries with mysqli_query(). For queries that return data (SELECT, SHOW), the result is a result-set handle; you fetch rows from it with mysqli_fetch_array(), mysqli_fetch_assoc(), or mysqli_fetch_row(). For queries that change data (INSERT, UPDATE, DELETE), the result is a boolean success indicator.

<?php
$host = "localhost";
$user = "phpuser";
$password = "";
$dbname = "Customer";

$cxn = mysqli_connect($host, $user, $password, $dbname)
  or die("Couldn't connect to server.");

$query = "SELECT * FROM Customer";
$result = mysqli_query($cxn, $query)
  or die("Couldn't execute query: " . mysqli_error($cxn));

while ($row = mysqli_fetch_assoc($result)) {
  echo $row['lastName'] . ", " . $row['firstName'] . "<br />";
}

mysqli_close($cxn);
?>

Other useful functions: mysqli_num_rows($result) tells you how many rows a query returned (useful for login validation), mysqli_insert_id($cxn) tells you the auto-increment value of the last inserted row (useful for relating tables), mysqli_affected_rows($cxn) tells you how many rows an UPDATE or DELETE touched, and mysqli_real_escape_string($cxn, $data) escapes a string so it's safe to use in a query.

Quote-escaping is essential for security. If you insert a user's name directly into a query and the name contains a single quote, the query breaks — or worse, an attacker can inject SQL. Always call mysqli_real_escape_string() on any string coming from outside your script before putting it in a query. The mysql extension had magic quotes to do this automatically; the mysqli extension does not, so you must do it yourself.

Key Ideas

  • The pattern: connect, query, handle result, close.
  • Use mysqli_connect, mysqli_query, mysqli_close.
  • Fetch rows with mysqli_fetch_assoc or mysqli_fetch_array.
  • Always escape strings with mysqli_real_escape_string before putting them in a query.

Improving Your PHP Programs

Automatically including helpers and reusing code.

Once your programs reach a certain length, you find yourself sprinkling include and require_once everywhere. Each new helper function requires another line at the top of every file. This gets tedious — and eventually, you forget one and the application breaks with a "function undefined" error.

The fix is auto_prepend_file. Set it in php.ini or in the Apache configuration with php_value. The file it names is automatically included before every PHP script runs. If it defines your helper functions and starts your session, every script gets them for free — no require_once needed.

<?php
// prepend.php — automatically included before every script
if (!isset($_SESSION)) {
  session_start();
}

function convertState($state) {
  $stateList = array(
    "WI" => "Wisconsin",
    "CA" => "California",
    "NY" => "New York"
  );
  if (array_key_exists($state, $stateList)) {
    return $stateList[$state];
  } else {
    return false;
  }
}
?>

The prepended file is included as if by require(), which means if it's missing, an error occurs. That's the right behaviour — you want to know if your helper file isn't loading. But be careful not to chain too many includes inside it, or every request gets slow.

Another code-reuse technique is to define classes for things that need to be reused across files. A User class, for example, can encapsulate all the logic for creating, authenticating, and updating users. Code that calls $user->authenticate() doesn't need to know how authentication works — just that the method exists and returns a result.

Key Ideas

  • auto_prepend_file automatically includes a file before every PHP script.
  • Use it for sessions, helper functions, and constants.
  • Don't chain too many includes inside the prepended file — it slows every request.
  • Classes are another way to reuse code cleanly.

Try It Yourself

  1. Create a prepend.php file with one helper function.
  2. Add a php_value auto_prepend_file "prepend.php" directive to your Apache config or .htaccess.
  3. Call the function from a different PHP script. Does it work without require_once?

Book Six · Web Applications · Chapter 26

Creating and Using a Web Service

Returning data in JSON or XML, and accepting input.

A web service is a program that returns data in a structured format — usually JSON or XML — for another program to consume. The consumer might be a JavaScript front end on another site, a mobile app, or a server-side program you've written yourself. Web services are how programs talk to each other over HTTP.

The simplest web service returns a date. Set the Content-Type header to tell the browser what format to expect, build your data, and call json_encode() on it. The result is a string that any JSON-aware consumer can parse. Return an array with named keys, and the consumer can access each field by name.

<?php
$header = "Content-Type: application/json";
header($header);

$returnData = array(
  "friendlyDate" => date("M d, Y"),
  "unixTime"     => time(),
  "month"        => date("M"),
  "dayOfWeek"    => date("l"),
  "year"         => date("Y")
);

print json_encode($returnData);
?>

Consuming a web service from PHP uses cURL — curl_init(), curl_setopt(), curl_exec(), curl_close(). The returned data is parsed with json_decode($output, true), which gives you an array. Or, if you requested XML, with SimpleXML or DOMDocument.

Returning XML is similar to returning JSON — build a DOMDocument, create elements for each field, append them to a parent, and save the XML. Set the Content-Type header to text/xml so the consumer knows what to expect.

Accepting input is a matter of reading $_GET or $_POST and validating the values before using them. For a web service, the common pattern is to accept a format parameter (json or xml) and return whichever the caller asked for. This gives consumers flexibility without maintaining two separate endpoints.

Key Ideas

  • A web service returns data in a structured format (JSON or XML) for another program to consume.
  • Set the Content-Type header, build your data, and encode it.
  • Consume with cURL, then json_decode or an XML parser.
  • Accept a format parameter to let consumers choose JSON or XML.

Validating Web Forms with JavaScript and PHP

Catching mistakes on the client, then catching them again on the server.

Form validation is the process of making sure the data submitted is correct and in the right format. There are two layers. Client-side validation happens in the browser, using JavaScript. Server-side validation happens on the server, using PHP. Both are necessary — client-side gives the user fast feedback; server-side is the only one you can trust.

Three rules govern the process. First, assume bad data. Assume every submission is wrong until proven correct. Second, never assume JavaScript. The user can disable it, and malicious users can send data directly to your server without ever loading your page. Third, mirror client- and server-side validation where it makes sense. If a ZIP code must be five digits, check that on both sides.

JavaScript validation attaches a handler to the form's submit event. The handler checks each field, gathers the names of the fields that failed, and either lets the form submit (if everything is valid) or prevents submission and displays the errors (if not). The feedback usually takes the form of a class added to the invalid field — a red background, plus a text message that becomes visible when the field is invalid.

$("#userForm").submit(function(e) {
  removeFeedback();
  var errors = validateForm();
  if (errors == "") {
    return true;
  } else {
    provideFeedback(errors);
    e.preventDefault();
    return false;
  }
});

function validateForm() {
  var errorFields = new Array();
  if ($("#name").val() == "") { errorFields.push("name"); }
  if ($("#email").val() == "") { errorFields.push("email"); }
  if ($("#password1").val() == "") { errorFields.push("password1"); }
  if ($("#password2").val() != $("#password1").val()) {
    errorFields.push("password2");
  }
  return errorFields;
}

PHP validation happens in the script that processes the form. The pattern: check required fields first (loop through a list of required field names, add an error for each one that's missing or blank). Then check each field's format — text should match a pattern, numbers should be numeric, emails should look like emails. Use filter_var($_POST['email'], FILTER_VALIDATE_EMAIL) for emails, preg_match for custom patterns, strlen for length checks.

Store the errors in $_SESSION['error'], redirect back to the form with header("Location: form.php"), and the form displays them. If there are no errors, redirect to a success page. The redirect-after-submit pattern ensures that refreshing the success page doesn't resubmit the form.

Key Ideas

  • Validate twice: client-side for speed, server-side for trust.
  • Assume bad data; never assume JavaScript.
  • JavaScript validation attaches a submit handler that prevents submission on error.
  • PHP validation checks required fields, formats, and business rules.
  • Redirect after submit to avoid duplicate submissions.

Try It Yourself

  1. Add JavaScript validation to a form for required fields and email format.
  2. Add PHP validation to the form's processing script for the same checks.
  3. Disable JavaScript and submit the form. Does PHP still catch the errors?

Building a Members-Only Website

Registration, login, authenticated pages, logout, and password reset.

A members-only site is a site where some pages require login. The application has four main pieces: a user database, registration, login, and protected pages. A fifth piece — password reset — rounds it out for real-world usability.

The database stores user information. At minimum: an auto-incrementing ID, an email address (also used as the username), a password (encrypted with crypt()), and a creation date. Additional fields — name, address, phone — are useful but optional. The email column should be unique, so no two users can register with the same address.

Registration shows a form, validates the input, checks that the email isn't already registered, encrypts the password, and inserts the row. Login shows a form, validates the input, looks up the user by email, compares the encrypted submitted password with the stored encrypted password, and — on match — stores user information in the session. Protected pages check the session to see if a user is logged in; if not, they redirect to the login page.

<?php
class User {
  public $id;
  public $email;
  public $firstName;
  public $isLoggedIn = false;

  public function authenticate($user, $pass) {
    $mysqli = new mysqli(DBHOST, DBUSER, DBPASS, DB);
    if ($mysqli->connect_errno) { return false; }

    $safeUser = $mysqli->real_escape_string($user);
    $query = "SELECT * FROM Customer WHERE email = '{$safeUser}'";
    if (!$result = $mysqli->query($query)) { return false; }

    $row = $result->fetch_assoc();
    $dbPassword = $row['password'];
    if (crypt($pass, $dbPassword) != $dbPassword) {
      return false;
    }
    $this->id = $row['id'];
    $this->email = $row['email'];
    $this->firstName = $row['first_name'];
    $this->isLoggedIn = true;
    $this->setSession();
    return true;
  }
}
?>

Password reset works like this: the user visits a "forgot password" page, enters their email, and submits. The script looks up the user, generates a unique hash, stores the hash in a resetPassword table along with the user ID and a timestamp, and emails the user a URL containing the hash. When the user clicks the link, they arrive at a page that asks for a new password, verifies the hash is still valid, and updates the password.

The full application is a good example of how all the pieces fit together: the database design from Book Five, the PHP and OOP from Book Four, the validation from earlier in Book Six, and the form handling from Book Two. Nothing in it is new — it's just the pieces, combined.

Key Ideas

  • Members-only sites have a user database, registration, login, and protected pages.
  • Encrypt passwords with crypt(); never store them in plain text.
  • Check the session on every protected page; redirect if not logged in.
  • Password reset uses a unique hash stored in a database and emailed as a link.

  2. Create a login form that authenticates against the database and sets a session.
  3. Create a protected page that redirects to the login page if not logged in.

Configuring PHP

The php.ini file, and the changes you'll actually want to make.

PHP's behavior is controlled through a configuration file called php.ini. Settings for sessions, error display, file uploads, and available modules all live there. The file's location varies by operating system and installation method — check phpinfo() to see which file PHP is actually reading.

Before editing php.ini, make a copy of the original so you can revert if something breaks. Then edit it in a plain text editor, save, and reload Apache for the changes to take effect. A change in php.ini applies globally — to every site on the server.

For site-specific or directory-specific changes, use .htaccess or Apache's VirtualHost configuration with the php_value directive. For programmatic changes inside a single script, use ini_set() and ini_get(). This lets you raise limits or change settings just for the code that needs it, without affecting the whole server.

session.gc_maxlifetime = 1440
session.name = PHPSESSID
session.cookie_domain =

disable_functions = exec
disable_classes =

display_errors = Off
error_reporting = E_ALL & ~E_NOTICE

upload_max_filesize = 100M
post_max_size = 100M
memory_limit = 256M
max_execution_time = 30

Common changes: lengthen session.gc_maxlifetime if users are being logged out too quickly. Set display_errors = Off in production so error messages don't leak pathnames or queries. Disable dangerous functions with disable_functions — exec and system are often disabled on shared hosting. Raise upload_max_filesize and post_max_size if you need to accept larger files. Raise memory_limit and max_execution_time if your script is timing out or running out of memory.

Every change you make is a trade-off. The largest file upload size is the largest file you'll have to handle. The longest execution time is the longest a script can hang before PHP kills it. The highest memory limit is the memory a script can eat before the server starts swapping. Choose values that fit your application, not values that simply remove every limit.

Key Ideas

  • php.ini controls PHP behavior globally.
  • .htaccess and php_value set it per-site; ini_set() sets it per-script.
  • Common changes: session timeout, error display, disabled functions, upload size.
  • Every limit is a trade-off — pick values that fit the application.

Building a Templating System

One header, one footer, one place to change them.

A template is a file that contains standard or boilerplate information used to create other files. When a site has only a few pages, maintaining a header and footer by hand is fine. When it has dozens — or hundreds — every change has to be made in every file. Templates reduce the header and footer to a single location. Change it there, and every page updates.

The template system in this chapter uses a PHP class called Page. It has three properties: $type (default, contact, and so on), $title, and $titleExtra. It has two main methods: getTop() builds the doctype, the opening <html>, the <head> section (from a text file plus the title), and the page top menu. getBottom() returns the footer and the closing tags.

<?php
class Page {
  public $type = "default";
  public $title = "My Web Site";
  public $titleExtra = "";

  public function getTop() {
    $output = "";
    $output .= "<!DOCTYPE html>\n";
    $output .= "<html lang=\"en\">\n";
    $output .= file_get_contents("pageHead.txt");
    if ($this->titleExtra != "") {
      $title = $this->titleExtra . " | " . $this->title;
    } else {
      $title = $this->title;
    }
    $output .= "<title>" . $title . "</title>\n";
    $output .= "</head>\n";
    $output .= file_get_contents("pageTop.txt");
    return $output;
  }

  public function getBottom() {
    return file_get_contents("pageBottom.txt");
  }
}

$page = new Page();
print $page->getTop();
?>
<div id="mainContent">
  <p>This is where content goes.</p>
</div>
<?php print $page->getBottom(); ?>

The two text files — pageHead.txt and pageTop.txt — hold the boilerplate. pageHead.txt contains the <head> open tag and any linked CSS or JavaScript files. pageTop.txt contains the menu structure and the opening <body>. The class includes these files with file_get_contents() and stitches them together with the doctype, html open tag, title, and head close.

To create a new page, instantiate the class, set the titleExtra property if you want a custom title bar, print the top, print your content, and print the bottom. Extending the template for different page types is a matter of checking $page->type inside _getHead() and including a different head file if the type is contact or special. The template stays small, the content files stay small, and the site stays consistent.

Key Ideas

  • Templates reduce repeated header and footer code to one location.
  • A Page class with getTop() and getBottom() handles the boilerplate.
  • Common HTML lives in small text files that the class loads.
  • Extend the template by adding page types — check the type in _getHead() and load a different head file.
